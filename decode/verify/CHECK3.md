## What this is

The decode campaign located every field in the **read** direction (device → bytes). This
backup tests the **write** direction: we authored each field ourselves to a chosen value and
ask the device to honour it. Restore `verify_findings_3.zip` via the **Backup menu** (it is a
full 8-bank backup; banks 5–7 are empty), then walk each bank/track and tick what matches.

## Reading conventions

- Banks map to device parameter pages. **Mid/readable** values (not pegged).
- **Bipolar** params: centre = 0, range −20…+20, so **+12** sits ~3/4 toward the right end.
- **Counts / enums** are exact. **Velocity** is 1:1 (0–127). Sustain byte 64 = one division.
- ⚠️ in a row = a caveat/low-confidence finding; read the note before judging a fail.

## Findings NOT directly exercised here

- Random **slew** (`value+0x13`) and **phase** (rotation of the 16-byte mod sequence) — need a live modulation sequence to be observable; verify by ear/behaviour, not a static read.
- Random **amount/lock** for params other than Velocity (one slot per param; only Velocity is set).
- Per-step **locks** other than velocity/sustain: Accent (id 0x18), Range (0x0c), Timing, CC (0x80) — the builder only emits velocity/sustain groove locks + pitch locks.
- **Multi-track selection set** (the extended per-pattern trailer the shipped builder under-emits) — only the single saved cursor is authored (Bank 4 T6).
- Per-cycle **track-param** overrides and **cycle pitch** overrides (cycle COUNT is exercised, Bank 0 T14).
- Pitch per-step **chord locks** (already shipped-proven & hardware-verified — a plain chord default is included at Bank 2 T5 instead).

## Round history

**Round 1** (`verify_findings.zip` → CHECK1.md). Bug found: `end_mark` builder used `(i+2) if i<n-1` — left slot 2 empty and shifted every later track by +1. Symptoms: banks 2/3/4 loaded but with the slot shift; **Bank 0 (16 tracks)** was rejected because the shift pushed T16 to out-of-range slot 17.

**Round 2** (`verify_findings_2.zip` → CHECK2.md). End-marker fix shipped (`next_slot − 1` per format rule); banks 0, 2, 3, 4 loaded with tracks on the named slots. **Bank 1 still didn't load.** Initial hypothesis (lock-summary + positional gap) was wrong — the gap was already gone in round 2.

**Round 3** (this file). True bug found: Bank 1 T4 wrote `timing_sub=1` to `steps+0x146`, but the 3-point enum's only valid values are **{3, 4, 5}** (`/4=3`, `/1=4` default, `/2=5`) — `1` is out of range and crashed the bank's load. **Fix:** `timing_sub=5` (= /2 subdivision, a non-default valid value).
